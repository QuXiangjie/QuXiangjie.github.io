Agent Settings Precedence

The same container as the Agent Isolation Layers post, with a different question: where each claude session reads its config from, and which value wins when two layers disagree. Order, highest first: managed policy, then programmatic options (settings, allowed_tools, agents…), then local, project and user files. setting_sources decides which of those three files load at all.

Purpose

Pick setting_sources and settings for a container that serves several tenants, and be able to explain the choice.

Done when you can answer
  1. For a given key, which value does session A end up with, and what changes when a layer isn't loaded?
  2. Which settings files do A and B share, and which can the agent itself rewrite?
  3. Why does a multi-tenant container use setting_sources=[] plus settings, and when would you add "project" back?

    The two layers tenants can't write are the two that don't come from setting_sources. Options have no file, so a tenant can't reach them. Managed policy is root-owned. Every file layer sits somewhere a session's bash can write, so loading it means trusting whatever was written there last.
